# V03-002 — Lenguaje semántico

Cuatro ejes independientes: procedencia de evidencia, cobertura, condición/severidad y modo de experiencia. El adaptador visual no calcula autoridad, confianza ni estado backend. Los consumidores deben pasar el estado real del contrato y conservar supporting text con fuente, fecha y límites. No convertir un porcentaje en alerta ni Demo en evidencia observada real.

| Estado | Significado / uso | No uso | Icono y label visible / nombre accesible | Rol de token |
|---|---|---|---|---|
| observed | Hecho leído de fuente identificada | Inferencia o dato demo presentado como Live | Eye / Observado | evidence.observed |
| inferred | Deducción con regla y evidencia trazable | Hecho confirmado | GitBranch / Inferido; borde discontinuo | evidence.inferred |
| manual | Aporte humano, autor/fecha | Confirmación automática | Pencil / Manual | evidence.manual |
| normalized | Transformación determinista conservando original | Dato nuevo o más confiable por definición | SlidersHorizontal / Normalizado | evidence.normalized |
| unknown | No existe base suficiente | Cero, false, sano | CircleHelp / Desconocido | evidence.unknown |
| unavailable | Fuente/consulta no accesible | Ausencia confirmada de entidad | CircleSlash / No disponible | evidence.unavailable |
| partial | Evidencia incompleta en scope explícito | Severidad alta | CircleDashed / Evidencia parcial | evidence.partial |
| conflict | Fuentes discrepan; mostrar ambas | Resolver automáticamente por color | Split / Conflicto de evidencia | evidence.conflict |
| Demo | Escenario sintético / sandbox | Salud real del tenant | FlaskConical / Demo | experience.demo |
| Live | Fuente real seleccionada; disponibilidad aparte | Garantía de freshness o conectividad | Radio / Live | experience.live |

Badges incluyen texto e icono decorativo `aria-hidden`. El texto visible es la fuente del nombre accesible; no sobreescribirlo con un aria-label incompatible. El contexto de procedencia es visible junto al badge, no depende de un tooltip hover. No usar `role=status` para cada badge estático: sólo anunciar cambios relevantes en el contenedor existente. Labels pueden localizarse, manteniendo el significado.

No es una escala ordinal de confianza: manual no implica peor que observed, y normalized describe una transformación, no autoridad. Un dato observado normalizado puede mostrar ambas etapas y la cadena de procedencia; EvidenceBadge presenta una etiqueta, no impone exclusividad al modelo canónico. Unknown/unavailable/partial/conflict deben mantener su alcance para no etiquetar como incierta toda la entidad por un atributo ausente.

## Coverage ≠ severity

CoverageIndicator acepta `covered`, `total` y un `scope` visible. Valores enteros seguros, 0 ≤ covered ≤ total, total > 0. `0/20` es cobertura conocida de cero; `null`, denominador 0, NaN, negativos, fracciones o covered > total son **Cobertura desconocida**, nunca 0%. `7/20` muestra counts + porcentaje + “parcial” en neutral. `20/20` muestra “completa”, sin convertirlo en Healthy. No es progressbar de una tarea ni evidencia de confianza estadística. Mostrar denominador/scope y tiempo de captura cuando exista.

| Condición real | Icono / texto | Uso / no uso | Rol |
|---|---|---|---|
| healthy | CircleCheck / Saludable | Condición explícita de fuente; no “sin datos” | severity.healthy |
| attention | TriangleAlert / Requiere atención | Revisión requerida; no cobertura baja por sí sola | severity.attention |
| degraded | CircleX / Degradado | Degradación explícita; no freshness aislada | severity.degraded |
| critical | OctagonAlert / Crítico | Urgencia confirmada; supporting reason obligatorio en contexto | severity.critical |
| stale | Clock / Desactualizado | Fecha fuera de umbral definido; no caída de servicio | severity.stale |

SeverityBadge es una presentación de estado **ya determinado**, no un clasificador. Legacy StatusBadge y criticality conservan contratos/colores. Nueva severity.critical usa danger para urgencia; el morado legacy queda explícitamente fuera de este nuevo eje hasta migración de cada dominio. Stale se representa neutral + reloj; el texto expresa tiempo, no alarma artificial. Conflicto usa atención y label de discrepancia, sin afirmar condición crítica del activo.

## Interacción

| Estado | Tratamiento | Semántica |
|---|---|---|
| hover | Fondo sutil, transitorio | No selecciona |
| selected | Fondo propio + marcador interior lateral, checkbox marcado | Persistente; puede coexistir con foco |
| current / active nav | Indicador y texto destacado | `aria-current=page`; no reutilizar checkbox |
| focus | Contorno exterior visible, offset | Sólo posición de teclado; nunca selección implícita |
| pressed | Feedback interior durante pulsación | Toggle persistente usa aria-pressed; no inferir desde CSS |
| disabled | Contraste atenuado y atributo nativo | No borrar explicación cuando es relevante |

High Contrast conserva labels, iconos y tipos de borde; usa Canvas/CanvasText/Highlight y system focus. Grayscale sigue mostrando las diferencias por texto/icono/patrón. No se implementa todavía selección compartida Table↔Graph: requiere contrato de estado, no únicamente CSS.
