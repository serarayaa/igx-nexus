## Target y reglas

Arquitectura KEEP, expresión EVOLVE. Nuevos roles deben describir intención y referenciar primitives/semantics existentes; no `card-gray-2` ni alias por cada pantalla. Component tokens sólo ante una decisión estable que no pueda expresar un rol compartido. No se añaden en esta entrega.

| Rol tipográfico | Target | Aplicación |
|---|---|---|
| page | 24 px / 600 / 1.2 | Overview y cabecera de página; nunca hero de marketing |
| section / entity | 20 px / 600 / 1.35 | Agrupación e identidad Asset 360 |
| table / metadata | 14 px / 400 / 1.5 | Dense data, detalles; permitir wrap |
| label | 14 px / 500 / 1.35 | Navegación y controles |
| caption | 12 px / 400 / 1.5 | Apoyo breve, no información esencial |
| metric | 36 px máximo / 600 | Conteo justificado, no colección de gauges |
| code | 14 px mono / 400 / 1.5 | Identificador exacto; copy cuando proceda |

Números alineados usan tabular-nums; mono se reserva a identificadores. No se importa General Sans: licencia/distribución no validada. Navy y cyan de marca se conservan; verdes comunican condiciones positivas sólo cuando la fuente lo permite. No gradiente ni imagery detrás de datos. Fotografía corporativa queda en contexto editorial opcional, fuera de las tablas.

**MOTION MUST EXPLAIN CHANGE.** Roles implementados: micro 120 ms, component 200 ms, panel 200 ms, workspace 320 ms; standard `(0.2, 0, 0, 1)` y decelerate espacial `(0, 0, 0.2, 1)`. Reduced motion resuelve todos a 0 ms conservando labels/feedback. Estos aliases preparan consumidores futuros; no instalan Motion Language completo ni autorizan animación que aparente causalidad o datos nuevos.

| Superficie | Tratamiento / condición |
|---|---|
| canvas | Fondo de aplicación |
| workspace | Región de trabajo sobre canvas; agrupación por espacio/títulos |
| primary | Contenido central, surface.base |
| secondary | Contexto auxiliar, surface.muted |
| panel / drawer | Contexto de entidad; encabezado, cierre, retorno de foco y scroll propio |
| card | Unidad independiente con acción/identidad propia; no envoltorio para cada dato |
| popover / dialog / floating | Elevación indica superposición; borde si aporta separación |

Preferir sections, dividers, whitespace y progressive disclosure. No glassmorphism; no bordes anidados por defecto. Radios vigentes no se cambian antes de revisar componentes representativos.

## Plan y aceptación establecidos antes del código

1. Inventario baseline y target documentados.
2. Aliases aditivos de typography/surface/evidence/coverage/severity/interaction/motion.
3. EvidenceBadge, CoverageIndicator y SeverityBadge; preservar APIs anteriores.
4. Pulir selección y pressed de foundations; composites como especificaciones, sin rediseño web.
5. Storybook con temas/densidades, estados adversos, interacción y alternativas de marca aisladas.
6. Validación de tipos, tokens, contrastes, tests existentes y evidencia visual.
7. Revisión humana; sólo después, tickets de migración progresiva por superficie.

Aceptación: aliases válidos y parity; coverage no deriva severity; labels/iconos entendibles sin color; counts inválidos no aparecen como cero/healthy; selección y foco coexisten; reduced motion también en contenedores anidados; forced colors conserva iconos/texto/bordes; no nuevos providers/contratos/dependencias visuales; build/tests verdes; branding aislado sin adopción. Matriz y resultados en `v0.3-visual-qa.md`.
