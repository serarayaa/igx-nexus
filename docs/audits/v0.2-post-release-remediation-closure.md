## Evidencia de verificación

### AUD-LIVE-001

- `mode="live"` sin provider falla cerrado también en runtime;
- `demoProvider` explícito bajo Live falla cerrado;
- wrappers que retornan `demoSnapshot` son rechazados por `dataMode`;
- Asset Explorer, Overview, Asset 360, Lifecycle y Technology Map comparten la misma invariante;
- Demo mantiene su comportamiento por defecto.

### AUD-API-001

- un timestamp GLPI tipo `2026-10-05 12:00:00` no recibe una zona horaria inventada;
- zero-dates y fechas imposibles no se promueven como tiempo canónico;
- el valor fuente queda preservado en `glpi.raw.*`;
- el round-trip GLPI → Fastify HTTP → Web mantiene el activo visible con temporalidad no disponible.

### AUD-DATA-001

- GLPI Assets/Computer deja de declarar cobertura de operational context que no observa;
- reconciliación preserva `undefined` si ninguna fuente tiene cobertura;
- si una fuente declara `[]`, el resultado conserva known-empty;
- IT/OT Intelligence representa el caso GLPI sin cobertura como `coverage.state = "unavailable"`.

### AUD-SEC-001

- HTTP plano sólo se admite para `localhost`, `127.0.0.1` y `::1`;
- destinos remotos requieren HTTPS;
- credenciales embebidas, query y fragment en `GLPI_BASE_URL` se rechazan;
- redirects autenticados están bloqueados;
- el test de seguridad usa dos servidores locales y verifica que el segundo origin recibe **0 requests** y **0 Authorization headers**;
- bodies upstream no se copian a mensajes locales de error.

## Resultado

Los cuatro hotfix prioritarios de v0.2.x seleccionados tras la auditoría post-release están **cerrados, mergeados y cubiertos por CI verde**.

Esto no significa que todos los findings de la auditoría estén corregidos. Los findings restantes continúan diferidos según el plan de fases y no se re-clasifican en este documento.

En particular, este cierre no amplía alcance hacia:

- rediseño UI/UX;
- nuevas fuentes Live;
- Intune tenant-side;
- performance/reliability de fases posteriores;
- infraestructura corporativa;
- ciberseguridad TI/OT futura.

## Frontera de release

v0.2 permanece **CLOSED**.

Los cambios de este ciclo son hardening post-release v0.2.x y no reabren el alcance funcional de la release.

La siguiente fase funcional debe respetar el roadmap vigente; en particular, v0.3 continúa reservada para UI/UX / Product Experience salvo decisión explícita de roadmap.
