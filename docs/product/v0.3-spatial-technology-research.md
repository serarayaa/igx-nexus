## Tecnologías de motion/render

“Bundle impact” es costo relativo/propuesta; tamaños finales de librerías **UNKNOWN** sin versión fijada, tree shaking y build representativo. No sustituirlo con tamaño unpacked npm. Medición del laboratorio propio en benchmark-results.json; no compara directamente estas bibliotecas.

| Opción / fuente / licencia | Bundle | Accessibility + fallback | Performance / maintainability / aplicación |
|---|---|---|---|
| CSS transitions; plataforma web, sin paquete incorporado | 0 dependencia | DOM semántico; reduced=0, no-motion igual estado | Opacity/transform 120–320ms, no loop; menor costo. Primera opción |
| [Web Animations API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API); API nativa, sin licencia de librería | 0 dependencia | Cancelar con reduced, focus separado; DOM equivalente | Continuidad de entidad en reveal/panel; cancelar animación interrumpida |
| SVG nativo; plataforma web | 0 dependencia; markup crece O(N+E) | labels + buttons HTML/list; forced colors | Escala acotada; readable/pickable; piloto de2.5D |
| Canvas2D nativo | 0 dependencia | HTML index/inspector obligatorio, hit testing propio | Draw batching; labels/picking complican; considerar sólo tras budget medido |
| WebGL nativo | shaders/picking propios, no librería | semantic2D/HTML obligado; context loss fallback | Buen throughput bruto; GPU/context/restoration/labels costosos; benchmark experimental |
| [Three.js](https://threejs.org/docs/); [MIT](https://github.com/mrdoob/three.js/blob/dev/LICENSE) | Mayor costo relativo; gzip UNKNOWN | DOM/list y foco sincronizado obligatorio | Cámara/occlusion/instancing; no aporta evidencia. No recomendado para interfaz inicial |
| [React Three Fiber performance](https://r3f.docs.pmnd.rs/advanced/scaling-performance); [MIT](https://github.com/pmndrs/react-three-fiber/blob/master/LICENSE) | Three + renderer; incremental gzip UNKNOWN | Igual limitación Canvas/3D | React integration y demand rendering; no justifica dependencia antes de necesidad |
| [D3](https://d3js.org/what-is-d3); [ISC](https://github.com/d3/d3/blob/main/LICENSE) | Modular; import individual, gzip UNKNOWN | DOM/SVG o Canvas según consumer | Escalas/layout; integración React requiere ownership claro. Investigar layout puntual |
| Sigma v3 + Graphology; MIT Sigma | renderer + graph structure; gzip UNKNOWN | Index semántico + focus/selection bridge | Candidato grafos grandes si SVG falla; requiere benchmark de labels/picking y deps separadas |
| Cytoscape.js; MIT core | motor integrado, gzip UNKNOWN | Index HTML alternativo | Candidato layout complejo; medir contra implementación equivalente, no elegir por marketing |

No decisión productiva de stack nueva: laboratorio usa **SVG + CSS + WAAPI**, con experimento2.5D y fallback. Recomendación provisional después de benchmark: mantener React/V03-002, SVG acotado y motion nativo para primer piloto, con gates de implementación. Canvas/Sigma/Three quedan investigación; benchmark renderer bare no selecciona librería.
