# IGX NEXUS v0.3 — Scope Freeze: IT CMDB

Estado: **APPROVED**  
Ticket: **V03-CMDB-00**

## Product statement

IGX NEXUS v0.3 entrega una **CMDB TI moderna y operable** sobre GLPI + GLPI Agent.

GLPI continúa como System of Record de CMDB/ITAM. NEXUS añade un modelo canónico, provenance, reconciliación, historial semántico, calidad de datos y una experiencia de producto orientada a investigación y operación.

## Exit gate

> Puedo buscar un equipo, abrirlo, entender qué es, dónde está, quién lo usa, qué hardware/software tiene, cuándo fue observado y qué tan completa es su información.

Este gate es más importante que el número de pantallas terminadas.

## Alcance funcional

V0.3 debe representar, cuando GLPI/Agent o una fuente aprobada lo soporte:

- computers, notebooks, desktops y servers;
- monitors, printers, peripherals y network equipment;
- software, versiones e instalaciones;
- users/owners/technicians como relaciones acotadas;
- entity y location;
- manufacturer, model y type;
- operating system;
- lifecycle/status;
- serial, asset tag e identificadores observados;
- relaciones entre CIs;
- cambios e historial semántico generado por NEXUS.

Ausencia de datos debe mostrarse como ausencia de cobertura, nunca rellenarse mediante inferencia silenciosa.

## IA aprobada

1. **Overview** — ¿Cómo está mi inventario TI?
2. **Assets** — explorar, filtrar, buscar y comparar activos.
3. **Asset 360** — comprender un CI completo desde una sola vista.
4. **Software** — productos, versiones, instalaciones y activos.
5. **Network** — equipamiento y datos de red realmente disponibles.
6. **Relationships** — relaciones con provenance y contexto.
7. **Lifecycle** — estado, antigüedad, renovación y evidencia.
8. **CMDB Health** — calidad y confiabilidad del inventario.
9. **Changes / History** — qué cambió, cuándo y según qué evidencia.
10. **Global Search / Command Palette** — acceso transversal.

## Asset 360

Asset 360 es la superficie central de v0.3 y organiza información por intención:

- Identity
- Assignment
- Hardware
- Operating System
- Storage
- Software
- Network
- Lifecycle
- Relationships
- History
- Provenance / Sources

No debe ser un formulario GLPI maquillado ni una lista indiscriminada de campos.

## Source strategy

- **GLPI**: System of Record para CMDB/ITAM y catálogos ya gestionados.
- **GLPI Agent**: observación automática del endpoint e inventario.
- **NEXUS**: modelo canónico, provenance, snapshots, history, reconciliation, quality y UX.
- **Entra**: identidad/account/org cuando se requiera.
- **Intune**: management/enrollment/compliance/primary user cuando se requiera.
- **Zabbix**: telemetría operacional; NEXUS no debe recrearla.

Cada source observation conserva su provenance. Una fuente nueva no pisa silenciosamente un valor canónico.

## Changes / History

GLPI aporta estado actual y, cuando corresponda, evidencia auxiliar.

NEXUS debe conservar snapshots normalizados y producir diffs semánticos para representar cambios de owner, location, software, lifecycle/status, hardware relevante, relaciones e inventory freshness.

No atribuir causalidad ni actor si la fuente no lo demuestra.

## Seguridad

- service identity dedicada;
- OAuth con scope mínimo;
- read-only por evidencia;
- deny-by-default;
- no direct DB writes;
- no secretos en Git;
- no elevación a Admin/Super-Admin para sortear 403;
- browser nunca consulta GLPI directamente.

## Accesibilidad

Gate transversal:

- teclado completo;
- foco visible;
- contraste objetivo WCAG AA;
- screen-reader semantics;
- reduced motion;
- estados no dependientes sólo de color;
- alternativa semántica para charts/graphs;
- reflow aproximado desde 320 px;
- focus trap correcto.

## Dirección visual

La CMDB debe aspirar a una estética corporativa premium: navy/graphite profundo, blue/teal controlado, acentos de estado sobrios, jerarquía tipográfica fuerte, profundidad sutil, dark/light y motion que explique contexto.

Evitar card soup, neon/cyberpunk, movimiento permanente, dashboards genéricos y estética de admin template.

La dirección final se valida en V03-CMDB-03.

## Non-goals

No pertenecen a v0.3:

- OT discovery;
- ciberseguridad TI/OT;
- vulnerability management;
- Wazuh / Greenbone;
- Malcolm / Zeek / CISA ICSN;
- IA/ML;
- anomaly detection;
- forecasting;
- autonomous automation;
- Digital Twin industrial.

Dirección futura propuesta:

- **v0.4 — OT CMDB & Discovery**
- **v0.5 — Cybersecurity**
- **v0.6 — Intelligence / Analytics & Data Science**
